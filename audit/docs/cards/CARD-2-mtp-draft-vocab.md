# CARD-2 MTP draft over a reduced vocabulary (FR-Spec style), plus draft-path trims
Question: The MTP draft runs the full 248320-row Q6_K LM head (796 MiB, 3.45 ms) to pick a top-10 candidate. Can the draft use only the most frequent N tokens without losing much acceptance?
Hypothesis: per draft token ~4.7 ms, of which the LM head is 3.45. With N = 32768 the head costs 3.45 x 32768/248320 = 0.46 ms, which saves ~3 ms per draft token and ~6 ms per n_max-2 step (~47 ms) = -13% step time. The acceptance loss is small if the N tokens cover >= 97% of the generated tokens (FR-Spec reports ~1-2% acceptance loss at 32k of 128k vocab). Net M2 wall +6..+12%. Cheaper drafts may also make n_max 3 the best setting. The verify stays full-vocab and exact, so the output distribution is unchanged (speculative decoding is lossless).
Files: `src/models/qwen35.cpp` MTP head (`build_lora_mm(head_w, cur, head_s)`, line ~665): draft graph only (ctx_dft / MTP build path), never the target `model.output` at line 237. Variant P (prefix, zero-copy): `ggml_view_2d(head_w, n_embd, N, head_w->nb[1], 0)`, which is valid if the tokenizer ids are roughly ordered by frequency (BPE merge order). Variant F (frequency permutation): at load, copy N selected rows of output.weight (row = token, quantised blocks are row-contiguous, so this is a byte copy) into a new tensor (N=32k: +105 MiB VRAM; serving has ~740 MiB free) plus an int32 id map; draft top-k ids map back through get_rows on the map. Logits size: the draft's backend top-k chain (`common/speculative.cpp` ~1838-1880, top_k 10) must work on N logits; if any host code assumes n_vocab-wide draft logits, pad with -inf through ggml_concat/fill instead (~1 MB GPU write, cheap). Env knob `P104_MTP_DRAFT_VOCAB=N` (0 = off) so A/B runs use one binary.
CPU pre-gate (no GPU): tokenize the 4 MTP workloads' outputs from runs/mtpk3-S-np1-r1.client.json (field text) and wiki.test.raw with `llama-tokenize` (CPU) and report coverage of ids < N for N = 16k/32k/64k (variant P). If coverage(32k) < 95%, build the frequency list from those token counts (variant F).
Control: v11-bin, MTP GGUF, serving config np1 -c 49152 f16 KV MTP n_max 2. B = candidate bin with P104_MTP_DRAFT_VOCAB=N (and with 0 as a dispatch check: must equal v11).
Gates: (1) dispatch: with the env set, profiler/trace shows the draft MUL_MAT at ne01 = N; with 0, identical to v11; (2) op correctness: test-backend-ops unchanged (no kernel change); temp-0 text identical to A on all workloads (verify is exact); (3) numerics: target KLD not affected by construction; run one kld ub1 as a regression check; (4) speed: mtpab ABBA, threshold mean M2 wall >= +4% and draft acceptance drop <= 3 pp; also try n_max 3 with N (one extra B arm); (5) VRAM (variant F) < +150 MiB, thermal.

Budget: builder 3 h (P 1.5 h, F +1.5 h); CPU build: llama + common only (~10 min incremental); GPU 35 min per iteration; max 2 iterations (iteration 2 = variant F or N=65536).
Bundling: "MTP/host" series with CARD-1 patch (if any); independent of the kernel cards; merge order last (touches only src/models + common).
Stop rule: acceptance drop > 5 pp at every N, or wall gain < +2%: stop. Do not touch the target LM head here (CARD-4).
