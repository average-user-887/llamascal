## 2. Provenance to repair before claiming the next result

1. **Loaded CUDA library is the top gap.** A/B commands name different binary paths, but both benches print `67df1fa`, and the v13/v14 manifests list the **same** `llama-bench` SHA and **different** `libggml-cuda.so.1.0.0` SHAs. That is consistent with a backend-only change, not proof of what was loaded. The handoff warns about `DT_RUNPATH`. Pin each arm's isolated executable and library directory; record real paths and SHA-256 of the driver-facing ggml CUDA DSO and other project libraries **actually mapped by the running process**, e.g. a sanitized process map/loader witness plus content hashes. Resolve symlinks; confirm paths again after startup if plugins load later. Never publish raw process maps or host paths. If intended DSOs are not witnessed, invalidate the timing despite the filename. Perform the tiny repaired paired confirmation, not a rerun of the whole release. [A meta](../receipts/runs/p104-v14-e2e-A1.meta.json) · [B meta](../receipts/runs/p104-v14-e2e-B1.meta.json) · [v13 hashes](../receipts/hashes/v13-HASHES.txt) · [v14 hashes](../receipts/hashes/v14-HASHES.txt).
2. **Artifacts and residence:** record exact source/dirty state, patch IDs, effective compile flags, toolchain/container digest where applicable, driver, runtime & device select, model SHA-256 and exact Hub revision, tokenizer/template and prompt token digest. Record actual model layer/backend/KV/state placement and peak VRAM, not merely `-ngl 99`. Log aliases (P104/P2000/P620), not serials/UUIDs, and record other-lane state, thermal/power/desktop policy and valid/invalid counts. The historical model label and file size do not prove a particular GGUF SHA; do not silently substitute the new manifest for historical file identity.
3. **Quality reference:** existing v14 KLD uses `k1-ub1-base.logits` from a quantized comparison lineage unless an unquantized source is independently shown; the published command does not pin full-precision reference bytes. ub1 reports mean **0.000609**, max **0.326049**, and same-top ~98.9% over its small probe; that is useful drift evidence, not exact or full-precision parity. For new numeric changes, compare matched control and candidate to the same pinned unquantized FP16/FP32 logits on a fixed tiny teacher-forced corpus, comparing mean **KL(ref‖candidate) − KL(ref‖control)**. Look only for reproducible worsening above calibrated one-sided tolerance; separately fail invalid output. Record exact sample size and max/tail as diagnostics, not a new release gate. If reference unavailable, mark speed-only exploratory rather than using Q8 as full precision. [Raw output](../receipts/runs/p104-v14-kld-ub1.out) · [command](../receipts/runs/p104-v14-kld-ub1.meta.json).
4. **Comparison boundary:** no shared-model generalization until identical fully resident GGUF bytes have been run on relevant cards. No percent stacking between different commits, fixture sets, prefill, decode, or MTP settings. Keep depth, batch, sampler/stops, layer placement and graph/cache state explicit. Do not infer what kernel ran from feature flags: capture separate dispatch evidence and clean timings with it off.
5. **Receipt integrity vs provenance:** 21 selected published files matched the snapshot manifest on independent readback. That establishes consistency of those text artifacts, not who ran them, exact runtime library selection, unrestricted coverage, or release asset reproduction.

## 3. Exact model pulls and common benchmark profiles

Use the [model manifest](PASCAL_MODELS.json) as the six-file shopping list; every entry names its Hub repo and exact Q4_K_M filename. Use the immutable Hub revision and exact publisher SHA-256/byte size listed for every file. Download one file at a time from a non-timing window with the [HF CLI](https://huggingface.co/docs/huggingface_hub/guides/cli): `hf download "$repo" "$file" --revision "$hub_commit" --local-dir "$model_dir"`. Hash local bytes, check exact size, and reject mismatches. TensorBlock removed Granite 3B Q4_K_M from its default branch; use the pinned pre-removal revision. If that weight object cannot be fetched, use the separately pinned Bartowski fallback as a new fixture with its own control. No weight object was downloaded during this audit. Do not download projectors. A named quant recipe may mix per-tensor quant types; record the actual type used by the patch.

- **Fit smoke once per profile:** use short text with MTP off, one slot, F16 K/V, batch and ubatch 128, fixed host threads, FA setting explicitly agreed and held, layer offload requested for all. Inspect real bindings; reserve usual desktop headroom and account for total expert weights. If either tiny model does not fit on the P620, reduce the common profile's context for **all** cards, or block that family and choose a separately identified smaller fixture. No CPU spill disguised as common.
- **First COMMON A/B:** one exact model from the family; pin `pp128` and `tg64` at depth 0, F16 KV, one slot, same settings on all tested cards. Stock v14 `llama-bench` uses internally generated vocabulary IDs (including for tg), not a sampled continuation. For matched synthetic timings use the same executable, library setup per arm, arguments, warmup/repeat count and profile order in fresh processes; don't claim externally fixed token IDs unless your harness supplies and pins them. [v14 token generation](https://github.com/average-user-887/llamascal/blob/585eb84/tools/llama-bench/llama-bench.cpp#L2171-L2227). An optional second depth such as 512 is a new profile after fit; do not require it per change. Record realized tokens and actual offload. For historical replay, use the historical profile instead (not these quick defaults). Start solo per card; conduct the staggered 2-up/3-up resource qualification separately before overlapping explorations. Publish **per-card delta** and dispersion; absolute rates are descriptive.
- **LADDER:** practical model/card pairs. Measure only the pair relevant to a candidate, then expand if justified. For larger prefill prompts or real MTP serving, define separate profiles; physical RAM/VRAM and K/V types must remain matched within each A/B.
- **Quick iteration:** two short warm interleaved pairs on one target where practical, dispatch witness out of band, fixed output check. One opposite-family smoke for shared code; no full matrix on each commit. A promising result gets exclusive confirmation and extra cards only for the claimed scope.

## 4. Ranked cards and estimates

These are **hypotheses and planning ranges**, not benchmark results or additive expectations. If a component accounts for fraction `f` of clean baseline wall time and its latency falls by fraction `r`, the throughput estimate is `1 / (1 - f*r) - 1`. Profiled CUDA-event shares approximate a ranking, not wall fractions; use clean A/B for the decision. All timings below are GPU timeboxes excluding one-time artifact setup. Prioritize the active bottleneck and cut a card when its stop rule trips.
